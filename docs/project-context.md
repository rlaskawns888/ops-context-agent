> Claude 프로젝트 파일로 올리는 문서. 단계가 끝날 때마다 "단계별 확정 결정" 섹션을 갱신한다.
> 마지막 갱신: 2026-11-19 / 현재 단계: 0. 준비

## 1. 배경과 목표

- 나: 8년 차 백엔드 개발자. 현재 폐쇄망 보안 운영 환경(대기업 고객사 상주)이라 업무에 AI 도입 불가.
- 문제: AI 직무 서류에서 "AI를 실제 업무에 적용한 경험"과 "AI가 틀렸을 때 원인을 찾아 개선한 경험"을 요구하는데, 답할 실무 경험이 없음.
- 해결: 보안·IT 운영에서 실제로 반복되던 문제(가이드 문의 대응, 계정·권한 처리, 원인 분석)를 외부 환경에서 재현하고, 운영처럼 측정·개선한 기록을 남긴다.
- 기간: 4주
- 결과물: GitHub 레포, 라이브 데모(Slack + 관리자 콘솔), 2분 시연 영상, 실험 리포트, 블로그 2~3편

### 타깃 공고
1. 현대오토에버 AI Agent 엔지니어 (1순위)
   - 담당: Agentic AI 아키텍처·Orchestration, MCP 기반 채널 연동, AI API·마이크로서비스·성능 튜닝, 업무 자동화
   - 우대: A2A·MCP 프로토콜, 지식그래프·온톨로지, 클라우드 배포, MLOps
2. 넥슨 AI Context 엔지니어
   - 담당: 사내 지식 Q&A 봇·업무 에이전트(Slack/Teams, 피드백 루프), 비정형 대화·문서에서 엔티티·관계·업무 규칙·암묵지 추출, 검색 최적화, 에이전트 장기 메모리, 사용 로그·피드백 분석
   - 자격: 임베딩·벡터 검색·청킹·리랭킹 개선 경험
   - 우대: GraphRAG, Neo4j, 그래프+벡터 하이브리드·멀티홉 검색, 시간에 따라 바뀌는 지식, 온톨로지 설계, 사람 피드백 기반 품질 개선, Slack 봇, LLM 출력 정량 평가
   - 게임 도메인 자격은 이 프로젝트로 채우지 않음

## 2. 무엇을 만드는가

Slack에서 동작하는 사내 IT 운영 Agent.
- 지식 Q&A: VPN, MFA, 계정 잠금, 보안 프로그램 오류, 권한 정책 등 문의에 근거와 함께 답변
- 업무 처리: 계정 잠금 해제, 티켓 생성·조회, 권한 신청을 MCP Tool로 실행 (실행 전 사용자 승인)
- 정책 검증(Guardrail): 권한 신청을 지식그래프로 검증 (예: 외주 인력 → 운영 DB 쓰기 권한 = 반려)
- 이관(Human-in-the-loop): 근거 부족·위험 요청은 담당자에게 대화 요약과 함께 이관
- 피드백 루프: 👍/👎와 담당자 수정 답변을 Context DB에 반영
- 지식의 원천은 "직접 쓴 가이드"가 아니라 흩어진 Slack 대화·티켓·회의록·문서에서 추출한 지식

## 3. 확정된 기술 결정

| 영역 | 결정 |
|---|---|
| 언어 | Python(주력), Cypher, SQL, TypeScript |
| API | FastAPI (모든 서비스) |
| Agent | LangGraph |
| 구조화 출력 | Pydantic |
| MCP | MCP Python SDK |
| 채널 | Slack (Slack Bolt for Python, 무료 워크스페이스) |
| 벡터 DB | PostgreSQL + pgvector |
| 그래프 DB | Neo4j AuraDB Free |
| 한국어 BM25 | rank_bm25 + kiwipiepy |
| LLM | Azure OpenAI 상위 모델 (저가 모델로 품질 낮추지 않음) |
| 임베딩 | text-embedding-3-large vs bge-m3 비교 실험 |
| 리랭커 | bge-reranker-v2-m3 |
| 관측·평가 | Langfuse |
| 프론트 | React + TypeScript (Vite) |
| 인프라 | Docker Compose, GitHub Actions |
| 클라우드 | Azure (Container Apps, Static Web Apps, ACR) — 학생 크레딧 사용 |
| 예산 | API 비용 월 1만 원 이내 (학생 크레딧으로 충당), 모델 품질은 유지 |
| 제외 | Spring Boot 사용 안 함, AWS 사용 안 함, 게임 도메인 제외 |

### 서비스 구성 (Docker Compose)
1. agent-api: FastAPI + LangGraph 오케스트레이터, Slack 연동, 검색, 메모리
2. mcp-server: 업무 시스템 API를 감싸는 MCP 툴 서버 (계정·티켓·권한)
3. ops-api: mock 업무 시스템 (계정, 티켓, 권한 신청) — FastAPI + PostgreSQL 별도 스키마
4. ingest: 지식 적재 파이프라인 (배치 실행)
5. admin-web: 관리자 콘솔 (React)

Agent는 업무 시스템을 직접 호출하지 않고 반드시 MCP를 거친다.
(면접 설명 포인트: 실무에서는 이 자리에 Spring 레거시 시스템이 오고, MCP 계층 덕분에 Agent 쪽은 바뀌지 않는다.)

## 4. 처리 흐름

### A. 지식 적재
수집(Slack 스레드·티켓·회의록·문서) → 정제(개인정보 마스킹, 중복 제거) → 청킹·임베딩 → LLM으로 엔티티·관계·업무 규칙·암묵지 추출(Pydantic 스키마) → 정답 샘플과 비교 검증 → pgvector + Neo4j 적재

### B. 질의 처리
Slack 질문 → 의도 분류 → 사용자 메모리 조회 → 하이브리드 검색(벡터 + BM25 + 그래프 멀티홉) → 리랭킹 → 근거 포함 답변 생성 → Guardrail → 응답

### C. 업무 처리
업무 요청 → 그래프로 정책 검증 → Slack 승인 버튼 → MCP Tool → ops-api 실행 → 결과 알림
위험하거나 근거가 부족하면 담당자 이관

### D. 피드백·배포
👍/👎·담당자 수정 → 관리자 콘솔 검수 → Context DB 반영 → 평가셋 편입
PR → GitHub Actions에서 핵심 평가 30문항 실행 → 기준 미달 시 merge 차단 → Azure 배포
